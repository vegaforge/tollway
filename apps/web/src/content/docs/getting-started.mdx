## Prerequisites

Node 22 or later and pnpm 10 or later.

## Scaffold a paid API

Create a new API with one gated route and an offline mock payment test:

```bash
npm create tollway -- --template express --dir my-api --yes
pnpm create tollway --template hono --dir my-api --yes
npm create tollway -- --template next --dir my-api --yes
```

The templates use Express, Hono, and Next 15 respectively. Mock mode is on by default. The mock signer does not create a secret key and is not suitable for real payments. Use `--force` to write into a non-empty directory; an existing `.env` is always preserved.

## Install and verify

```bash
git clone https://github.com/vegaforge/tollway.git
cd tollway
pnpm install
pnpm build
pnpm test
```

## Run the demo

The demo drives one paid x402 request from challenge to signed receipt, with no network needed:

```bash
MOCK_MODE=true pnpm --filter @vegaforge/tollway-demo start
```

Mock mode is the only demo path that works today. Without `MOCK_MODE`, the demo calls the mainnet OpenZeppelin facilitator URL, sends no API key, and uses placeholder addresses, so a real testnet run fails. Fixing those defaults is tracked in [#113](https://github.com/vegaforge/tollway/issues/113).

## Next.js route paywalls

For one App Router handler, wrap its export with `withPaywall` from `@vegaforge/tollway-adapter-next`:

```ts
// app/api/paid/route.ts
import { withPaywall } from "@vegaforge/tollway-adapter-next";
import { gate } from "@/lib/paywall";

export const GET = withPaywall(gate, async (_request, { receipt }) =>
  Response.json({ receiptId: receipt.receipt.id }),
);
```

For a group of paths on Next 16, configure the proxy entry point:

```ts
// proxy.ts
import { paywallProxy } from "@vegaforge/tollway-adapter-next/proxy";
import { gate } from "./src/paywall.js";

export const proxy = paywallProxy({ routes: [{ path: "/api/paid", gate }] });
export const config = { matcher: ["/api/paid/:path*"] };
```

The proxy runs on Node.js. It strips a caller-supplied Tollway receipt header and forwards only the receipt returned by the gate. In a route handler, `getProxyReceipt(request)` reads and schema-validates that receipt. The proxy also returns the `PAYMENT-RESPONSE` and `TOLLWAY-RECEIPT` headers to the caller.

## When a payment fails

The client retries an x402 payment only when retrying cannot pay twice. If the
service refuses the signed payment before settling it, for example because the
authorization expired, the client checks the policy again and signs a fresh
authorization for the same terms. If the service reports the same payment as
still settling, the client waits the `Retry-After` it sends and resends the
identical payment. Anything that may have settled, such as a 5xx after the
signed request went out, is never retried: `pay()` rejects with
`AmbiguousSettlementError`, and you reconcile before paying again. The client
README has the full table and the `retry` option.

## What is built today

Tollway is pre-release and no package is published to npm yet.

Implemented and tested:

- `@vegaforge/tollway-core`: the canonical receipt with an Ed25519 signer, the policy and budget engine, and the default model router.
- `@vegaforge/tollway-server`: the payment gate for x402 and MPP charge, an HTTP facilitator client, a mock facilitator and MPP charge handler, and in-memory and Redis settlement caches.
- The Express, Fastify, Next.js, and Hono adapters.
- `@vegaforge/tollway-client` orchestration (policy, routing, receipt verification). You supply the payment signer.
- `@vegaforge/tollway-channels` open, commit, and close against an injected channel adapter.
- `@vegaforge/tollway-reconcile` drift detection and `@vegaforge/tollway-observability` metrics, exports, and webhooks.

Still open, each with a tracking issue:

- Real MPP charge settlement ([#100](https://github.com/vegaforge/tollway/issues/100)) and a real MPP channel adapter ([#101](https://github.com/vegaforge/tollway/issues/101)).
- Channel recovery ([#38](https://github.com/vegaforge/tollway/issues/38)) and router promotion to channel mode ([#105](https://github.com/vegaforge/tollway/issues/105)).
- x402 V2 wire compatibility ([#43](https://github.com/vegaforge/tollway/issues/43)) and a production x402 client signer ([#102](https://github.com/vegaforge/tollway/issues/102)).

The README's Status section has the full list.
