---
title: Vercel AI SDK tool
description: Give a model a paid_fetch tool that pays for URLs within a Tollway budget, with the safety defaults a model-driven caller needs
---

`@vegaforge/tollway-ai-sdk` gives a model a `paid_fetch` tool built with the AI SDK's `tool()` helper. The model asks for a URL; the tool fetches it through your paid fetch, which pays the 402 if the policy allows it, and hands the model the response and a short receipt summary. A refused payment comes back as a structured result the model can read, so a blocked payment does not end the run.

The paying is not done here. The tool calls the paid fetch you give it, such as `createPaidFetch` from `@vegaforge/tollway-client` (tracked in [#201](https://github.com/vegaforge/tollway/issues/201)), which reads the challenge, runs the offer checks and policy, signs, and verifies the receipt.

## Install

```bash
pnpm add @vegaforge/tollway-ai-sdk ai zod
```

`ai` 7 and `zod` 4 are peer dependencies.

## Use it

```ts
import { createPaidFetchTool } from "@vegaforge/tollway-ai-sdk";
import { generateText, stepCountIs } from "ai";

const result = await generateText({
  model,
  tools: {
    paid_fetch: createPaidFetchTool({
      paidFetch, // pays 402s; set its offerChecks.maxAmount for a per-call price ceiling
      allowedOrigins: ["https://api.example.com"],
      policy, // the same PolicyEngine the paid fetch uses, to report the budget left
    }),
  },
  stopWhen: stepCountIs(5),
  prompt: "What is the XLM/USD price?",
});
```

## Safety defaults

| Default | Why |
| ------- | --- |
| `allowedOrigins` is required and non-empty. A URL on any other origin is refused before a request is made. | The model chooses the URL. |
| Only `GET` unless `methods` allows more. | A write a model was talked into is worse than a read. |
| The model may not set `Authorization`, `Cookie`, `PAYMENT-SIGNATURE`, `X-PAYMENT` or `TOLLWAY-RECEIPT`. | Payment and credential headers belong to the host. |
| Redirects are not followed (`redirect: "error"`), and a response from another origin is withheld. | A redirect would leave the allowed origins after the check. |
| The body is cut at 32 KiB (`maxBodyBytes`), counted in bytes, and the result says when it was cut. | A large body would flood the model's context. The download stops at the cap. |
| Only `http` and `https` URLs pass the input schema. | |
| The result carries `id`, `amount`, `asset`, `payee` and `model` of the receipt, never its signature or the payment header. | The full receipt reaches the host through the client's events and receipt store. |

## Results

A call that went through returns:

```ts
{ status: "ok", httpStatus, paid, body, truncated, contentType?, receipt?, remainingBudget? }
```

`remainingBudget` is set after a payment when you pass `policy` and the engine reports headroom: `{ asset, payee, remaining, limitedBy }`, where `remaining` is the base units left (or `null` when nothing limits that asset and payee).

A refusal the model can act on returns `{ status: "blocked", rule, detail }`. The rules are `origin-not-allowed`, `method-not-allowed`, `header-not-allowed`, `redirect-not-allowed`, `counterparty-quarantined`, `offer-network-mismatch`, `policy:<rule>` for a policy block (for example `policy:budget`), and `offer-check:<check>` for an offer check (for example `offer-check:maxAmount`, the per-call price ceiling).

Everything else throws: an abort, a network failure, and a payment whose outcome is unknown. The run sees those, and the client's events still report what happened to the payment.

## Cancellation

`execute` forwards the AI SDK's `abortSignal` to the paid fetch as `init.signal`. An abort before the call sends nothing. After that, what happens is the paid fetch's to decide: one that honours the signal stops before it signs, and once a signed payment has left, the Tollway client reports the outcome through its events and receipt store rather than dropping it. The tool rethrows the abort either way.

## Example

`examples/agent-tools` runs `generateText` with the AI SDK's mock language model: one paid fetch on an allowed origin, then a refused one on another origin.

```bash
pnpm turbo run build --filter='@vegaforge/tollway-example-agent-tools...'
pnpm --filter @vegaforge/tollway-example-agent-tools ai
```

Until `createPaidFetch` ships, the example pays through a stand-in paid fetch built on a real Tollway client and policy.
