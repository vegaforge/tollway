## Summary

Streams live updates from `@vegaforge/tollway-service` to the dashboard over server-sent events, so the Overview, Receipts, Channels, and Anomalies views update without page reloads, and a dropped connection resumes from where it left off without losing or duplicating events.

**Service (`apps/tollway-service/`)** — new Hono app with:
- `GET /v1/events/stream` — streams six typed event types (`receipt.created`, `channel.opened`, `channel.closed`, `budget.warning`, `anomaly.detected`, `metrics.delta`) with monotonically increasing integer ids, optionally filtered by `?types=`, requiring `Authorization: Bearer` with the `read` scope.
- In-memory `EventBuffer` (default 1 000 events). `Last-Event-ID` resumes from a specific id; if that id has aged out, a `reset` event tells the client to refetch its snapshot.
- Heartbeat comment line every 15 s to keep idle connections alive through proxies.
- Abort cleanup via Hono's `stream.onAbort`.

**Dashboard proxy (`apps/dashboard/src/app/api/events/stream/route.ts`)** — Next.js route handler that validates the session cookie (same `authorizeRequest` path as every other route), adds `SERVICE_API_KEY` from the server environment, forwards `Last-Event-ID` and `?types=`, and streams the response body unchanged. The key never reaches the browser.

**Shared schemas (`apps/dashboard/src/lib/event-schemas.ts`)** — Zod v4 schemas for all seven event types (including the control `reset` type), mirrored from the service. `parseSseEvent` validates each event before it touches state.

**`useEventStream` hook** — opens an `EventSource`, tracks `connecting / live / reconnecting / paused` status, coalesces bursts via `requestAnimationFrame` (capped at 500 events), and dispatches validated events to per-type handlers registered by consuming hooks via `registerSseHandler`.

**Updated hooks** — `useReceipts` prepends and deduplicates `receipt.created`; `useOpenChannels` appends on `channel.opened` and updates status in place on `channel.closed`; new `useAnomalies` prepends `anomaly.detected`; new `useOverviewStats` tracks counters from `metrics.delta`. All refetch their snapshot on `reset`.

**New views** — `AnomaliesView` replaces the previous `EmptyState`. `OverviewLiveSection` shows live counters on the Overview page. `StreamStatusBadge` appears on Receipts, Channels, and Anomalies panels.

**Configuration** — `apps/dashboard/.env.example` gains `SERVICE_URL` and `SERVICE_API_KEY`. `apps/tollway-service/.env.example` documents `PORT` and `SERVICE_API_KEY`.

**Ordering note** — IDs are monotonic within one service process. With multiple replicas a client reconnecting to a different replica receives a `reset`; a Redis Streams-backed buffer would fix this. Documented in `docs/dashboard-data-contracts.md`, "Stream ordering and resume".

## Notes for the reviewer

- **Known issues for preflight**: `pnpm install` must run first to pick up the new `apps/tollway-service` workspace package and its dependencies (`hono`, `@hono/node-server`). The lockfile will need updating.
- The service's `stream.write(": heartbeat\n\n")` call uses Hono's raw write method. If the installed version of `hono` exposes a typed `writeComment` or similar on the SSE stream, that is preferable and can be swapped in without touching any other code.
- Tenant scoping from #231 has not landed; there is no `tenantId` on the stream yet. When #231 lands, the `requireApiKey` middleware can be extended to extract and enforce tenant scope on the stream, matching the existing pattern on other routes.
- The `reset` event on a fresh connection (no `Last-Event-ID`) uses `reason: "filter-changed"` as a default label. `"fresh-connection"` would be more descriptive; happy to change if the maintainer prefers.
