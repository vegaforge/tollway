Add ECDSA P-256 receipt signing with algorithm-bound keys (#169). New `EcdsaP256Signer` (WebCrypto, `namedCurve: "P-256"`, SHA-256) supports `generate(keyId?)`, `fromPkcs8(der, keyId?)`, `fromJwk(jwk, keyId?)` with a cross-check that the declared public half matches the private material, `sign(message)` emitting IEEE P1363 (`r || s`, 64 bytes) with `s` normalised into the low half, and `publicJwk()` in the key-set document shape. New `EcdsaP256Verifier` handles the single-trusted-key case, rejecting cross-algorithm receipts, length mismatches, and high-S signatures (`s > n/2`). The key-set `keySetEntrySchema` is now a discriminated union on `kty` accepting `kty: "OKP", crv: "Ed25519"` and `kty: "EC", crv: "P-256"` entries; `createKeySetVerifier` binds each key record to the algorithm declared in its `alg`, so an Ed25519 key can never verify an ES256 signature or the other way round. A new exported `derToP1363(der)` helper is strict: it rejects trailing bytes, non-minimal lengths and integer encodings, negative integers, and an r or s that is zero, oversize or not below the P-256 order, all with the new code `invalid-signature-encoding`; `normaliseLowS` moves `s` into the low half. A new `RECEIPT_ALGORITHMS` registry (`Ed25519`, `EdDSA`, `ES256`) names every algorithm the key-set verifier accepts; `Ed25519` and `EdDSA` are treated as the same algorithm so pre-#167 receipts still verify. Every existing Ed25519 receipt test passes untouched. `Ed25519Verifier` also accepts `EdDSA` and returns false, instead of throwing, for a malformed trusted key. The published vectors gain verify-only ES256 cases.
