Publish receipt signing keys as JWKS-style key sets with a caching verifier (#167). `@vegaforge/tollway-core` gains `createKeySetVerifier({ url | document, fetch?, clock?, minCacheMs?, maxCacheMs?, unknownKidRefetchCooldownMs? })` (a `ReceiptVerifier` that fetches, caches under `Cache-Control: max-age` clamped between min/max bounds, rate-limits unknown-`kid` refetches, and fails closed without a fresh-enough cache), plus the `KeySetDocument` / `KeySetEntry` / `KeySetFetcher` types and the `keySetDocumentSchema` / `keySetEntrySchema` Zod parsers. Ed25519 keys follow RFC 7517 + RFC 8037 (`kty: "OKP"`, `crv: "Ed25519"`); each entry has a `status` of `active`, `retired` (with `retiredAt`) or `revoked`, with revoked meaning reject every receipt the key ever signed and retired meaning verify only receipts whose `issuedAt` is strictly before `retiredAt`. `Ed25519Signer` grows `fromJwk(jwk, keyId?)` (private-JWK import, with a cross-check that the declared public half matches the private material) and `publicJwk()` (public-JWK export in the key-set document shape). `@vegaforge/tollway-server` adds `renderKeySetResponse(document, { maxAgeSeconds })`, a framework-agnostic `{ status, headers, body }` helper every adapter can forward. WebCrypto + `fetch` only, so the verifier runs in Node 22+, edge runtimes and the browser.
