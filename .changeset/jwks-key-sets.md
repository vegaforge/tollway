Publish receipt signing keys as JWKS-style key sets with a caching verifier (#167). `@vegaforge/tollway-core` gains `createKeySetVerifier({ url | document, fetch?, clock?, minCacheMs?, maxCacheMs?, defaultCacheMs?, staleIfErrorMs?, failureBackoffMs?, unknownKidRefetchCooldownMs? })`, a `ReceiptVerifier` that caches under `Cache-Control: max-age` within bounds, fails closed once an expired copy cannot be refreshed (so a revocation is seen within one cache lifetime plus `staleIfErrorMs`), backs off while the URL is down, rate-limits unknown-`kid` refetches, and never throws. `ReceiptVerifier` gains an optional `check` that returns a reason, which `verifyReceipt` reports (revoked, retired, unknown key, algorithm mismatch, bad signature, key set unavailable). Documents with duplicate `kid` values or bad key material are refused (`parseKeySetDocument`, new error codes `invalid-key-set` and `key-set-unavailable`). It also adds the `KeySetDocument` / `KeySetEntry` / `KeySetFetcher` types and the `keySetDocumentSchema` / `keySetEntrySchema` Zod parsers. Ed25519 keys follow RFC 7517 + RFC 8037 (`kty: "OKP"`, `crv: "Ed25519"`); each entry has a `status` of `active`, `retired` (with `retiredAt`) or `revoked`, with revoked meaning reject every receipt the key ever signed and retired meaning verify only receipts whose `issuedAt` is strictly before `retiredAt`. `Ed25519Signer` grows `fromJwk(jwk, keyId?)` (private-JWK import, with a cross-check that the declared public half matches the private material) and `publicJwk()` (public-JWK export in the key-set document shape). `@vegaforge/tollway-server` adds `renderKeySetResponse(document, { maxAgeSeconds })`, a framework-agnostic `{ status, headers, body }` helper every adapter can forward. WebCrypto + `fetch` only, so the verifier runs in Node 22+, edge runtimes and the browser.
