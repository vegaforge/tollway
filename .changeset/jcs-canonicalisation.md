Make receipt canonicalisation conform to RFC 8785 (JCS) and publish test vectors (#165). `canonicalJson` and `canonicalBytes` now reject lone surrogates in string values or object keys, `undefined` inside an array, `bigint`, functions, symbols, and non-plain objects (`Date`, class instances, `Map`, `RegExp`) with `TollwayError("canonicalization-failed", ...)` instead of silently emitting wrong bytes or surfacing a raw `TypeError`. Key order (UTF-16 code units), number formatting (ECMA-262 `ToString(Number)`) and string escaping (only control characters, `"` and `\`) were already correct and are unchanged. A new published vector set at `docs/receipt-vectors/canonical-and-ed25519.json` lets a verifier in another language check its canonicalisation and Ed25519 verification against vectors signed with the RFC 8032 section 7.1 TEST 2 key, including the RFC 8785 section 3.2.3 and 3.2.2.2 examples, with every non-ASCII character escaped in the file, and `packages/core/src/receipt/vectors.test.ts` keeps the vectors and the implementation in step. Every schema-valid v1 receipt that contains no lone surrogate signs and verifies byte-for-byte identically to before.
