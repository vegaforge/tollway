# Generated API reference

The docs site has an "API reference" section: one page per public entry
point at `/docs/api/<package>` (`core`, `server`, `client`,
`adapter-express`, `adapter-fastify`, `adapter-next`, `adapter-next-proxy`,
`adapter-hono`, `channels`, `reconcile`, `observability`, `theme`,
`theme-preset`), generated from the TSDoc comments and rendered by the
existing Fumadocs theme. Types link across packages, for example
`SignedReceipt` on the server page goes to `/docs/api/core#signedreceipt`.
Every export of `@vegaforge/tollway-core` and `@vegaforge/tollway-server`
now has a doc comment. Closes #252.

Technical shape. `apps/web/typedoc.json` runs TypeDoc 0.28.20 with
`typedoc-plugin-markdown` 4.14.1 and `typedoc-plugin-frontmatter` 1.3.3 over
each package's `src/` entry in one program (`apps/web/typedoc/tsconfig.json`
maps the workspace imports to source), so the build needs no `dist/` and
cross-package references resolve. A local plugin
(`apps/web/typedoc/plugin.mjs`) names each page after its package, adds the
`title` and `description` frontmatter Fumadocs requires, rewrites links to
site URLs, writes the folder's `meta.json`, and prints the exports with no
doc comment. `pnpm run api` (run by `prebuild` and `predev`) generates the
pages, then `typedoc/check-api.mjs` fails the build unless every entry point
has a page in the sidebar. `treatWarningsAsErrors` makes a broken `{@link}`
or a public type that references an unexported one fail the build. The
web build's turbo inputs include `packages/*/src`, and
`apps/web/netlify.toml` rebuilds on a change there.

Choices the issue left open:

- Generated pages are gitignored and built in CI, not committed with a
  drift check: the CI `build` job runs the generation anyway, so a committed
  copy would only add a second source of truth and a check to keep in sync.
- `treatWarningsAsErrors` rather than `treatValidationWarningsAsErrors`:
  in TypeDoc 0.28 a link that fails to resolve stays a plain warning, so the
  narrower option would not fail on it (verified by the test).
- `@vegaforge/tollway-adapter-next/proxy` is documented as its own page next
  to the theme's `./preset`, since it is a public entry point too.
  `create-tollway` is a CLI with no library entry, so it has no page.
- `fumadocs-typescript` is not used; the reference pages are plain MDX.
- The reference does not link to source lines (`disableSources`): the
  paths would point at a local checkout.
